## 恢复状态的共同规则

停止请求表示操作员要求结束当前工作。能否重算还取决于算例已提交的结果、实际阶段证据、输入身份和进程状态。普通队列、边界实验、CLI 异常处理及旧中断登记遵循同一优先顺序。

| 已有状态或证据 | 恢复动作 | 新增 CFD 预算 |
| --- | --- | --- |
| 唯一 success/failed/review 训练行，设计及来源一致 | 保留终态及人工决定，补齐队列、诊断和阶段记录 | 0 |
| 没有终态行或仅 interrupted，Solve/Post 已完成且全套身份核验通过 | 提取真实指标并补记 success/review，更新诊断、checkpoint 和 Pareto | 0 |
| 几何或 CFX 明确失败，或记录了自然非零退出 | 补记 failed，保留现场；停止 token 不覆盖失败 | 0 |
| 不完整尝试，有匹配的停止凭据且没有终态/失败证据 | 确认进程退出，按日志归档历史，在原 run_id 和坐标上重算 | 消耗实际尝试预算 |
| 同上，但 Solve 已核验完成、仅 Post 未完成，且物理签名未变 | 只归档 Post 产物（`scope=post`），保留 Solve 证据并只重跑 Post | 消耗实际尝试预算 |
| 不完整 running 阶段，没有停止凭据 | 停止并要求检查；旧中断由 retry-interrupted 明确确认 | 不执行 |
| 前一阶段完整、下一阶段从未启动 | 确认无残留进程并移交新 owner，核验输入后继续下一阶段；不重跑前一阶段 | 按实际尝试计数 |
| 输入、候选、完成凭据或归档身份冲突；retry-interrupted 登记后其确认的凭据改变 | 拒绝恢复，不以自动重算掩盖冲突 | 不执行 |

`recover_recorded_case()` 负责终态恢复；它不开始新 attempt、不归档、不启动工具。完整 CFD 的恢复复用 CFX runner 的只读验证，包括候选/网格、物理输入、求解控制、最终 out/res、收敛或送审证据，以及 Post 产物身份。普通队列在某一点没有预算时继续扫描其他可补记点。边界实验先恢复所有预留点并持久化状态，再进行 singles/pairs/extension 的前序门控。

完成结果的生产签名可以是当前签名或经 `--accept-input-change` 明确接受的旧签名。补记行保留实际 attempt 的生产签名；没有 attempt 凭据的历史结果沿用训练行、队列或边界预留的签名。兼容确认不跳过几何和 CFX 的证据核验，恢复期间当前物理输入发生变化时仍不记录成功标签。

自动重试、旧中断登记和归档都使用共同的失败证据检查。已提交 CSV 的结果优先于后来到达的中断，避免重复 run_id。归档重放检查原 attempt 的身份，并检查源目录及已移动目录的失败凭据和活动进程。活动进程按 PID 加启动时间判断：停止凭据和活动凭据记录启动时间，旧凭据及 CFX `pids` 文件以写入时间为上限，晚于该时间启动的同号进程视为 PID 复用。停止前已接受（`--accept-input-change`）的旧签名仍可重试，但只在签名未变时保留 Solve。完成结果的证据变化会被拒绝，不会转为可重算的中断。

## 进程与重评的生命周期

子进程从启动、活动凭据登记到等待退出都由同一清理路径保护；活动凭据写入被中断或失败时，也会结束已启动的子树。自然非零退出先传回对应阶段，真正取消产生的退出另行标记。GUI/CLI 并发停止使用序列化合并，JSON 写入使用独立临时文件，保留停止范围。GUI 写入停止凭据后最多等 CLI 8 秒完成自身清理再强制结束进程树；运行级停止在下一个算例开始前生效，不为未开始的点创建 attempt 或 interrupted 行。重评 Post 抛出异常时操作凭据记为 failed。

CFD attempt 和重评 Post 有独立的 owner。重放 Post 时创建新的操作 owner，旧停止请求不会阻止重放，也不会触发整例归档。重评先补齐已有诊断行，再把训练行发布为 review；在诊断提交中途停止时，结果尚不能人工接受，重放会复用已完成的 Post 补齐数据。最终求解证据必须对应最后一次实际启动的求解：发生 continuation 时必须是 attempt 1，正常退出且证据一致；初始 attempt 0 不能替代失败或缺少输出的 continuation。这也适用于没有新 reason_code 的历史凭据。

## 行为回归矩阵

### 旧中断登记与重放的验收条件

`retry-interrupted` 必须先核对唯一队列/边界归属、坐标、签名及进程退出，再根据实际阶段证据作决定。已有失败行还必须对应相同的失败阶段。登记只写中断确认，不启动工具或归档；拒绝时训练行、队列和现场文件保持原样。

| 实际阶段证据 | 明确确认后的预期行为 |
| --- | --- |
| Geometry running；Pre running/returned；Solve running，均无明确失败或已结束求解的矛盾证据 | 保留原 run_id，零预算不执行；有预算整例归档重算 |
| 初始 Solve 正常达到迭代上限，continuation 尚未返回，初始输出身份一致 | 初始结果保留为历史，有预算整例重算 |
| Post running/returned，最终 Solve 已收敛或待审核，输入及完成证据一致 | 保留 Solve，仅归档并重跑 Post；returned 的输出不能充当完成结果 |
| 与上行相同，但操作员已接受物理输入变化 | 保留旧 attempt 的生产签名，按新输入整例重算 |
| Solve 已返回结束输出、尚无合法最终接受判定；数值失败；Post complete；人工否决 | 拒绝按中断登记，保留现场，使用相应检查/重评入口 |
| CSV 失败阶段与凭据不同，或完成输入/文件冲突，或仍有活动进程 | 拒绝登记且不改现场 |
| Post 登记后求解文件改变，或归档重放时确认凭据改变 | 拒绝归档和计算；不能降级为整例重算掩盖冲突 |
| Post 归档中途退出后，操作员接受了物理输入变化 | 将原归档日志扩展为整例归档后重放，再按新输入重算；范围扩展中途退出也可重放 |
| 归档已提交，但替换 attempt 尚未落盘 | 从最后一份归档恢复原输入及确认凭据；重新判断保留 Solve 或扩展为整例归档，不丢失输入关系 |

`tests/test_legacy_recovery_state_machine.py` 从真实 Python 执行链生成阶段凭据，在持久化 Geometry/Pre/Solve/continuation/Post 的 running、returned 和终态时模拟旧进程退出；只替换外部程序。每个允许场景验证登记、零预算、有预算和重复续跑，检查实际工具调用、归档范围、历史列、唯一 run_id 及待审核结果不进入 Pareto。普通队列和边界预留都覆盖有/无 CSV 的恢复入口。拒绝场景逐项改变失败阶段、求解终态、输入身份、结果/控制文件及进程状态，并逐字节比较拒绝前后的现场。输入未变时，两种历史/当前签名公式均须核验输入并保留 Solve；人工接受的其他输入只允许重算。Post 归档中途退出，以及随后接受输入变化而扩展归档的再次退出，都须能重放完成。

新增恢复分支时，先在对应的真实阶段边界复现失败，再补一项允许行为及其相邻拒绝行为，最终通过登记后的续跑验证；单独测试登记谓词或用不完整的合成凭据证明可登记不足以验证这条链路。

| 测试文件 | 覆盖的跨阶段行为 |
| --- | --- |
| tests/test_interrupt_state_machine.py | 失败与停止竞态；CSV 提交后中断；自然非零退出；正常退出后迟到的停止；PID 复用；已接受输入变更；子进程已启动而活动凭据写入失败；并发停止范围合并；无标记崩溃；归档身份冲突 |
| tests/test_resume_state_machine.py | 普通/边界预算 0 恢复 success/review；恢复不占下个点预算；队列后续扫描；前序阶段门控；连续两次停止；CSV/诊断/checkpoint/Pareto 一致；人工决定保留；输入或证据变化拒绝；Post 中停止只重跑 Post 及证据变化时整例重算；接受输入变更后重算 |
| tests/test_reassessment_state_machine.py | restart 非零退出、结果歧义、缺失/无法解析 out；历史无 reason_code 凭据；Post 中断重放；prepared 及 CSV/queue 分步提交的重放；人工否决保护 |
| tests/test_legacy_recovery_state_machine.py | 真实阶段边界的旧中断登记及预算重放；Post 只重跑自身；无 CSV/边界归属；待审核保护；完成输入冲突拒绝；登记后求解文件变化拒绝；接受物理变化后保留原签名整例重算；Post 归档中断重放 |
| tests/test_recovery.py、tests/test_reliability.py | 同 run_id 重算与历史归档；旧中断登记及 continuation 中断；登记后凭据变化（含归档中途两侧）拒绝；GUI 等待 CLI 清理；CFX 完整链路恢复；锁、签名和异常处理 |

测试使用临时目录、合成 CFD 文件和外部工具替身，进程清理及并发停止测试使用可回收的真实 Python 子进程。真实工程求解器的长时间停止/重启仍需在明确配置和预算下单独验证。
